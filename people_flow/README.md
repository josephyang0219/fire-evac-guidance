# 人偶人流追蹤與計數

建築模型裡的人偶由地板下的磁鐵**手動**拖動。模型負責「看到人偶」，本資料夾負責「誰是誰、往哪走、算幾人」。

## 依實體模型 `實體模型檔案/fire_model.blend` 的條件

（先前討論的「1:10、正上方俯拍」與誤用的 v12 數據都已作廢。）

- 每層是 245×245 mm 的樓層盒，室內淨高約 **97 mm**，開放空間以可插拔閘門板分隔；出口是西北、東南兩座梯塔。
- 障礙物尺寸推算比例約 **1:40** → 人偶約 **40 mm** 高、肩寬約 10 mm。
- 每層 4 台 8735 在四邊中央，鏡頭離地約 100 mm、**往中心傾斜 18°**，幾乎是俯拍。
- 粗估（112° 水平視角、576 px 寬）：鏡頭附近的人偶約寬 30～55 px；房間另一側（約 220 mm 外）只剩約 13 px → 計數區放在**離該鏡頭近的半邊**，遠的半邊交給對面的節點。
- 4 台鏡頭視野大量重疊 → 每個節點只負責自己那一側的計數區，避免同一個人偶被多個節點重複計數；全層合計交給伺服器。
- A/B 區要依閘門板的擺法與梯塔門的位置劃設（例如「往西北梯塔」方向的進出），擺法改變就要重設區域。

| 檔案 | 說明 |
|---|---|
| `hub_people_flow/PeopleFlow.h` | 追蹤＋A/B 區域計數核心（不依賴 Arduino，固定大小陣列） |
| `hub_people_flow/hub_people_flow.ino` | 8735 韌體：推論 → 追蹤 → 畫面疊 A/B 區域、ID、人數；序列埠每秒回報，輸入 `r` 歸零 |
| `test/sim_test.cpp` | 電腦端模擬測試（手動拖動的停頓／忽快忽慢、漏偵測、誤判、交界晃動、並排） |

## 判斷規則

1. **配對**：前後幀用 IoU＋中心距離貪婪配對；漏偵測後重新出現時，允許距離隨消失時間放寬（`maxSpeed`），但上限 `maxGap` 小於 A、B 間距，一次配對不可能從 A 直接跳到 B。
2. **確認**：新目標連續命中 `confirmHits`（3）幀才算數 → 濾掉一閃而過的誤判。
3. **保留**：消失 `keepMs`（1 秒）內回來沿用同一個 ID；在畫面邊緣消失的視為走出畫面，提早刪除。
4. **計數**：A、B 之間留緩衝區；只有「最後在 A、之後進 B」才算 A→B 一人（反向同理）。在交界前後晃不會重複計數。
5. **移動中**：平滑後速度 > `movingSpeed`（畫面寬 5%／秒）。

## 模擬測試結果（每種情境 200 次）

| 情境 | 計數準確率 |
|---|---|
| 單一人偶等速／手動拖動 | 100% |
| 3 人同向、雙向交錯、並排靠近 | 100% |
| 漏偵測 25% | 100% |
| 交界前後晃動（不應計數） | 100%（0 次誤算） |
| 每幀 30% 機率出現隨機誤判框 | 97.0%（只有少算） |

最後一項是刻意的嚴苛條件；補訓後誤判會少很多。

```bash
cd people_flow/test
python -m ziglang c++ -w -std=c++17 -O2 -I../hub_people_flow sim_test.cpp -o sim_test.exe
./sim_test.exe
```
（`pip install ziglang` 即可取得 C++ 編譯器）
