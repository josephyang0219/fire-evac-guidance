## 結論

1. **最大的問題是光線不夠，不是焦距**：模型內部平均亮度只有 21–53（一般室內畫面約 90–150），兩成像素幾乎全黑 → 感光元件拉高增益，雜訊大、對比低，看起來也會「糊」。
2. **焦距確實要調近**：鏡頭出廠多半對焦在 50 cm 以上，模型走廊的物體在 3–20 cm，中段的障礙物、閘門都不清楚。建議對到約 10–12 cm（走廊中段），近端與遠端靠景深兼顧。
3. **偏紫／洋紅**：PS5268 在混合光（窗光＋室內燈）下白平衡偏掉，可能也有紅外線混入；436B 最明顯。
4. **405B 要先現場看**：鏡頭方向、排線、是否被線材或 OLED 擋住。

## 調焦步驟（每台約 5 分鐘）

1. 在走廊中段（離鏡頭約 10–12 cm）放一張印有細字或棋盤格的紙，打開光源。
2. 鏡頭若是可旋的 M12 鏡頭：先輕刮掉固定膠，慢慢旋轉（每次 1/8 圈）。
3. 每轉一次跑 `frame_check.py`，看那台的「清晰度」數字，找最大值；或在中控台按「畫面」放大看細字。
4. 定位後點一點膠固定。四台用同一個距離，訓練資料才一致。

## 光影變化：訓練上的優化

**先把變因變小（效果最大）**
- 模型內部加固定光源（例如天花板夾層貼一圈 5V 暖白 LED 燈條，經擴散片），讓「室內自然光」變成可控的基準光。展示現場的燈光不同時，差異會小很多。
- 韌體鎖曝光與白平衡（SDK 範例 `Multimedia/examples/ISPControl/Exposure`、`WhiteBalance`、`WideDynamicRange`、`ImageTuning`）：固定曝光時間／增益、固定色溫，避免同一場景忽亮忽暗、偏色。交系統程式評估。

**資料**
- 實景錄製（補拍清單 A 段）每一組場景都在 3–4 種光下各錄一次：模型燈全開、只有室內自然光、偏暗（關一半）、手電筒側光；空場景（負樣本）也一樣。用 `cam_capture` 直接錄板子畫面，保留真實的雜訊與偏色。
- E holdout 依光線分組，分別量誤判與漏判，才知道哪種光最弱。
- 量化校正圖（轉 .nb 最多 10 張）要涵蓋亮、中、暗三種，不要只挑漂亮的。

**資料增強（Blender 渲染圖與實景都套）**
- 亮度／gamma 0.3–1.5、對比 0.6–1.3；低光模擬：先降亮度再加 Poisson＋Gaussian 雜訊。
- 色偏：色相 ±10°、紅藍通道各自 0.8–1.2 倍（模擬洋紅偏色與色溫）、飽和度 0.5–1.3。
- 模糊：失焦（高斯 σ 0.5–2）、輕微動態模糊；JPEG 品質 40–90。
- 鏡頭：魚眼變形與暗角（四台都是廣角，邊緣壓縮明顯）。
- Blender 端：燈光強度與色溫隨機、加入很暗的場景，再套上面的感光元件後處理，縮小「乾淨渲染圖」和實際畫面的差距。

**驗收**
- 每種光下 E holdout：火、煙、障礙物的召回率，以及空場景的誤判數；調焦、加燈、鎖曝光前後各量一次比較。

## 色偏分析（第二次畫面，RGB 平均）

| 板子 | 亮處（>120）R / G / B | 暗處（<40）R / G / B |
|---|---|---|
| 405B | 192 / 180 / 116 | 10 / 8 / 12 |
| 436B | 140 / 149 / 147 | **37 / 15 / 57** |
| 33C1 | 144 / 156 / 125 | 23 / 18 / 29 |
| 0280 | 154 / 157 / 136 | 19 / 14 / 23 |

亮處接近中性（略偏暖），**偏紫只出現在暗處：綠色被壓低、紅藍偏高**。原因推測（由大到小）：
1. 光線太暗 → 感光元件高增益；白平衡在室內光下把 R、B 放大較多，暗處的雜訊與黑位偏差跟著被放大 → 陰影變洋紅。補光後增益降低，這個現象會變小。
2. 紅外線：若鏡頭沒有濾紅外線的鏡片（IR-cut），窗光的紅外線會進到 R、B 像素；黑色 PLA 對紅外線反射不低。驗證：電視遙控器對著鏡頭按，中控台畫面看得到亮點就代表紅外線會進來。436B 最嚴重，可能剛好朝向窗光或鏡片不同。
3. 模型內部幾乎全黑，自動白平衡缺少參考色，估計容易飄。
對策：補可見光（最有效）；韌體評估固定白平衡、低光時降飽和（SDK `ISPControl/WhiteBalance`、`ImageTuning`）；必要時換有 IR-cut 的鏡頭；訓練時加「陰影偏洋紅」的色偏增強。
## 436B 色偏補償（FW 2.9，四台已 OTA）

傍晚室內光（比上午更暗，四台亮度 14–22）。對照圖 `2026-11-26_436B_色偏補償比較.jpg`：左上預設、右上 `sat=30`、左下 `awb=0 red=400 blue=320`、右下 `awb=0 red=400 blue=440`。

| 設定 | 暗處 R/G/B | 亮處 R/G/B | 看起來 |
|---|---|---|---|
| 預設 | 21 / 14 / 28 | 124 / 136 / 123 | 偏紫 |
| **sat=30（自動白平衡）** | **18 / 15 / 23** | **134 / 135 / 124** | **紫色明顯減少，亮處維持中性 → 採用** |
| awb=0 red=400 blue=320 | 20 / 17 / 16 | 151 / 148 / 90 | 暗處中性，但整體偏黃綠 |
| awb=0 red=400 blue=440 | 19 / 14 / 20 | 141 / 132 / 112 | 仍略偏紫 |

結論：暗處的紫是「偏移」不是「比例」，手動白平衡的紅藍增益只能顧亮處或暗處其中一邊；降飽和兩邊都改善、又保留自動白平衡對光線變化的適應力。目前 436B 設為 `sat=30`（`python flash_tools/set_isp.py 436B sat=30`，存在 devices.json）。**裝 LED 補光後要重量一次**，增益降低後可能可以把飽和度調回來。
