# 燒錄方式檢查：把本組模型蓋進 SDK（DEFAULT_YOLOV7TINY）（2026-11-18）

## 現在的做法

- 把 SDK 的 `variants/common_nn_models/yolov7_tiny.nb` 換成本組模型（原檔備份成 `.coco_backup`），程式用 `DEFAULT_YOLOV7TINY`。
- 目的：任何資料夾的 sketch、任何一台電腦、遠端用 arduino-cli 都能直接編譯燒錄，不會被 SDK 的 `ino_validation` 擋下。
  - `CUSTOMIZED_YOLOV7TINY` 只有在 sketch 放進 SDK 的 `libraries/NeuralNetwork/examples/` 底下才編得過（2026-11-04 實測，論壇也有同樣案例），每改一次程式就要複製一次，不適合遠端。

**結論：用 USB＋arduino-cli 遠端燒錄，這個做法可行，也比「放進 examples」方便（不考慮 SD 卡）。** 但有 3 個風險要處理：

| # | 風險 | 後果 | 處理 |
|---|---|---|---|
| 1 | SDK 重裝、更新、換一台電腦，`yolov7_tiny.nb` 悄悄變回 COCO 模型 | **不會報錯**。COCO 的類別 0～6（person、bicycle、car…）會被當成櫃子、紙箱…，伺服器算出錯的路線 | 新增 `fire_evac_v2/tools/check_sdk_model.py`：直接讀 .nb 檔頭的張量形狀，印出輸入尺寸和類別數；加 `--expect-classes 6`（重訓後改 7）放在燒錄腳本最前面，不符就停 |
| 2 | 6 類換成 7 類時，SDK 模型、韌體、伺服器沒有一起換 | 伺服器原本只認得 6 類，收到類別 6（人偶）會 IndexError 當掉 | 本次已修：`evac.CLASSES` 加上 `person`，人偶不算障礙物；不認得的類別一律略過 |
| 3 | 其他範例（`20_yolo`、`21_yolo_person`）也會跑到本組模型 | 測官方範例時結果怪 | 任務板已記；要跑官方範例前先換回 `.coco_backup`，用上面的工具確認是 80 類 |

## 不考慮 SD 卡（2026-11-18 使用者決定）

- 官方 Wi-Fi OTA 要把 NN 模型放 SD 卡、程式改用 CUSTOMIZED，**和本專案的做法衝突，不採用**。
- 燒錄一律走 USB＋arduino-cli（模型在 Flash，蓋 SDK 的 DEFAULT 模型），燒錄前先跑 `check_sdk_model.py`。

## 另外：下載模式要手動按鍵

現在燒錄前要手動進下載模式（按住 Function，按一下 RST）。這是遠端燒錄真正卡住的地方：8 台裝在麵包板座裡就按不到。

- 板子選單有 `Auto Flash Mode`（`01_AutoUploadMode=Enable`），可以試試看能不能免按鍵。
- 不行的話，就在裝進麵包板座前先燒好，或讓 USB 線從座外端開口拉到外面，需要時再按鍵。
