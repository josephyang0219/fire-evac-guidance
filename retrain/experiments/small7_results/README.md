# 小規模 7 類補訓結果（2026-11-18，可行性評估）

**目的**：先用少量渲染圖確認「加人偶（第 7 類）」行不行，並找出正式重訓前要修的地方。這不是要上板的模型。

## 設定

- 電腦：使用者的 RTX 5060。腳本 `retrain/experiments/small_retrain_pc.py`。
- 渲染：`dr_render.py` 用 `model_oled_ceiling/fire_model_oled_through_hole.blend`（閘門 94 mm），只有 1F。
  - 有目標物的 360 張，加上空場景 60 張，共 420 張。切成 train 323 張、val 97 張。
- 訓練：從 6 類 `best.pt` 微調成 7 類，`--img 576 576`，batch 16，40 輪，每輪約 16 秒，總共約 11 分鐘。

## 判讀

1. **人偶可以學。** 只用 389 個訓練樣本、40 輪，AP@0.5 就到 0.92。框高 ≥ 30 px 時召回率 77～91%，可以當人流計數的基礎。
   - 小於 30 px 的人偶樣本太少（共 4 個），還不能下結論。因為渲染時人偶多半離鏡頭近，正式渲染要補遠處的小人偶。
2. **煙和瓦礫是 0，問題出在渲染資料，不在模型。** 我把標註框畫在圖上檢查過：
   - **煙**（[範例](smoke_label_example.jpg)，紅框是煙）：框裡幾乎看不到煙。`dr_render.py` 用「有煙、無煙各渲一張，亮度差超過 6% 的像素」當可見範圍。可是 Cycles 低取樣時，煙的體積散射本身就會讓雜訊差超過 6%，所以框是被雜訊撐大的。加上煙的密度下限 0.01／mm，很多煙本來就淡到看不見。結果是「看不見的東西被標成煙」，模型學不起來。
   - **瓦礫**（[範例](rubble_label_example.jpg)）：瓦礫被渲成一團全白、沒有紋理的形狀，跟亮牆面分不開。這是因為 `Rubble_A_pile`／`Rubble_B_beam` 原本的材質在這個場景的燈光下過曝，不像其他障礙物有隨機換色。
3. 舊的 6 類（櫃子、紙箱、桌椅、閘門）AP@0.5 是 0.66～0.91。偵測頭因為類別數變了要重學，又只有 40 輪，這組數字不能拿來和舊模型（val 0.78）比；正式訓練後再比。

## 修正方案（正式重訓前）

| # | 修正 | 改哪裡 |
|---|---|---|
| R1 | 煙的可見判定：兩張都先降噪（或提高取樣），門檻從 6% 提高到約 15%，並且可見像素要佔投影範圍一定比例（例如 ≥ 25%）、做形態學開運算去掉零星點，達不到就**不標**也不留這團煙 | `dr_render.py` `SMOKE_REL_DIFF`、`make_smoke` 密度下限、標註段 |
| R2 | 煙的密度下限從 0.01 提高到約 0.03／mm，讓大部分煙看得到 | `make_smoke` |
| R3 | 瓦礫隨機換材質：灰、褐、混凝土色，加雜訊紋理，避免過曝 | `dr_render.py` 放障礙物時對類別 3 套隨機材質 |
| R4 | 補遠處小人偶（框高 12–30 px），以及 2F 場景（原本的 A2） | 人偶擺放範圍、渲染 2F |
| R5 | 資料量回到正式規模（約 3,000 張以上），訓練 80～150 輪 | Colab 或這台 RTX 5060（每輪約 16 秒／323 張，3,000 張約 2.5 分鐘／輪） |
| R6 | 仍然要有實拍照片和實拍測試集（原本的 A3），合成 val 分數高不代表實景好 | `retrain/補拍清單.md` |

修完 R1～R3 後，先用同樣的小規模（420 張、40 輪）重跑一次，確認煙和瓦礫的 AP 有起來，再做正式規模。
